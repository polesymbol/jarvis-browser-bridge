# Relay Server (v1)

WebSocket relay between the Chrome extension and the Jarvis driver.
**Passthrough only** — it never stores page content, DOM snapshots, or screenshots.

## Run

```bash
# private/dev (plain ws, localhost only)
node relay/server.js

# beta (wss with real certs)
TLS_CERT=/path/to/cert.pem TLS_KEY=/path/to/key.pem PORT=8787 node relay/server.js
```

`GET /health` returns `{ ok: true, rooms: <n> }` (plain-ws mode only).

## Auth

Both sides open a WebSocket and send first:

```json
{ "v": 1, "type": "pair.request", "role": "extension", "driver", "key": "<connector-key>" }
```

The key is the connector secret generated by the extension (shown once, API-key
model). The relay hashes it (SHA-256) to derive the session room and never logs
or persists the raw key. Wrong/short keys and non-pair first messages are
rejected with close code `4401`. One connection per role — a new connection
replaces a stale one.

After pairing, every message is forwarded to the peer. `session.abort` from
either side tears the room down. Permission enforcement stays in the
extension's service worker; the relay cannot escalate.

## Test

```bash
node relay/test.js   # full protocol self-test, no browser needed
```

## Driver CLI (Jarvis side)

```bash
node driver/driver.js --relay ws://127.0.0.1:8787 --key <connector-key> observe
node driver/driver.js --relay <url> --key <key> act --type click --target "Add to cart" --tier T1
node driver/driver.js --relay <url> --key <key> abort
```

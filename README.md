# Jarvis Browser Bridge

> **🧪 Free beta is open.** Your AI assistant drives **your own Chrome** — your IP, your logged-in sessions — under permissions you control. Not a competing browser. An extension of the assistant to the rest of the web, with explicit per-site consent. **Join:** install from [Releases](https://github.com/polesymbol/jarvis-browser-bridge/releases) and follow Quick start below — then tell us what broke via [Issues](https://github.com/polesymbol/jarvis-browser-bridge/issues).

## ⚠️ Safety first: fresh Chrome profile required

This extension can see every page you visit. **Install it only in a fresh Chrome profile** — no saved passwords, payment methods, addresses, or other personal data.

- **Never use your main profile.** Banking, email, saved passwords — keep all of that in a separate profile this extension never touches.
- **Never sign into Chrome with your existing Gmail** to create the profile. Chrome Sync would pull your saved passwords, bookmarks, payment methods, and addresses from your Google account straight into this profile — defeating the entire purpose. Use a brand-new email or skip sign-in entirely.
- Inside the fresh profile, log into **only** the sites you want the assistant to automate. Login itself is the consent mechanism.
- **Enforced, not just advised:** the extension detects Chrome sign-in via the identity API. If the profile is signed in, the relay stays **hard-blocked** — no connection, no warn-and-allow — until you explicitly acknowledge that specific account. Signing in mid-session drops the relay immediately. (No sign-in = Sync is definitively off.)

## How it works

Three parts, one protocol (v1):

| Part | Dir | Role |
|---|---|---|
| **Extension** | `extension/` | MV3 Chrome extension (the hands). Observes the active tab, enforces permissions **locally**, shows consent prompts, executes approved actions. |
| **Relay** | `relay/` | WebSocket pairing server. Pairs extension + driver by connector key. Stores no page content. |
| **Driver** | `driver/` | The assistant-side CLI. Can only *propose* actions — the extension decides, you approve. |

```
Driver (assistant)  ──wss──▶   Relay   ◀──wss──  Extension (your Chrome)
  proposes action        pairs by key         enforces permissions locally
                                              └──▶ consent prompt ──▶ you approve
                                              └──▶ executes ──▶ result
```

Live public relay: `wss://relay.musebridge.avinyahub.com`

## Consent, not just capability

- **Permission modes** in plain language: *Readonly*, *Ask for some actions*, *Always ask* — per site.
- **Action tiers:** T0 observe, T1 low-risk, T2 state-changing, T3 sensitive. T3 *always* asks, in every mode, no exceptions.
- **Grants that end prompt fatigue:** approve *Allow once*, *For 1 hour*, *For 1 day*, *For 1 week*, *Until a date & time you pick* (up to 31 days), or *Always on this site* (permanent, per site) — so a multi-step job on one website or account doesn't ask you to approve every click. Timed grants cover T1/T2 on that one site and expire hard, with no silent extension. **T3 critical actions still ask every single time — inside a timed grant, on a permanently granted site, in every mode — because one mistaken irreversible action is the failure this product refuses to automate.** One-click revoke anytime; everything audit-logged.
- **Unmissable prompts:** in-page consent banner (works with the panel closed) plus toolbar badge. No silent approvals.
- **Connector key:** API-key model — generated once, shown once, revocable/regenerable.
- **Kill switch** (`Ctrl+Shift+K`), per-site allow/block, exportable audit log.
- **Page content is data, never instructions.** The driver never executes anything found in page content.
- **Sign-in takeover:** when a login is needed, control returns to you. Passwords never leave your machine.

## What the assistant sees when it observes

An observe snapshot contains: the page's interactive elements (buttons, links, inputs) with labels; the page's **readable text** from the top page and every iframe, including open shadow-DOM content (capped at 15,000 characters per frame, 60,000 merged); and, for video/audio, playback state plus **caption/subtitle transcripts** when the player exposes them (capped at 12,000 characters per element). That's what lets the assistant actually *read* a course or video page instead of guessing from buttons. Snapshots transit the relay (see the security note below) and are never stored by it. One deliberate exception to "observe changes nothing": reading a transcript may switch a disabled captions track to hidden mode so its cues load — nothing appears on screen, and no other page state changes.

## The panel: "The Instrument"

v0.2.1 ships a dark precision-instrument UI — warm tinted ink, ember reserved for decisions, serif voice for consent, monospace for keys and timestamps — with a day mode (warm paper light theme) on a sun/moon toggle. Kill switch docked in a sticky bottom bar.

## Status

**v0.2.33** — free beta open (October 2026). Full consent stack verified live: OS notification toast, audible chime, in-page banner, toolbar badge, capped re-raise of swallowed toasts, audit-logged throughout. Navigate works from browser-internal pages; relay hardened (rate limits, room caps, payload limits). Observe snapshots carry the page's readable text from every frame (top page + iframes, incl. open shadow DOM) plus video/audio caption transcripts — course and video players are legible to the driver, not just clickable. Grants are now flexible: 1 hour, 1 day, 1 week, a custom "until" date & time you pick, or permanent per site — while critical T3 actions keep asking every time, grant or no grant. v0.2.16 adds consent-lifecycle acknowledgements (received → shown → waiting heartbeat → verdict → applied/failed) so the driver reports PEER_DOWN, PROMPT_NOT_SHOWN, NO_ANSWER, DENIED, or APPLIED_UNCONFIRMED instead of one opaque timeout; act ids are deduped so a resent act can never double-apply; and a consent timeout never auto-denies — the proposal stays queued in the panel. v0.2.17 makes key rotation real: one click in the panel generates a new key (shown once), revokes the old key at the relay, disconnects the connected driver, and invalidates every grant made under the old key — grants are bound to the key epoch that created them, so rotation leaves 0 active grants until you deliberately re-grant. A driver holding the old key gets an explicit KEY_ROTATED error, not a timeout. v0.2.18 moves the relay WebSocket out of the MV3 service worker — whose suspensions were the bridge's #1 outage cause — into the persistent offscreen document: the worker now expresses transport intent over runtime messages and consumes forwarded protocol strings, while consent enforcement stays exactly where it was, in the worker. The offscreen document is transport only (it pairs, forwards, queues, and reconnects with backoff; it can never approve, deny, or apply an action), a keepalive watchdog recreates it if the socket stays down over 30s, and pending proposals verifiably survive both worker and offscreen restarts. v0.2.19 replaces positional snapshot refs with stable element ids (stamped on the element itself, never reused, adopted across re-injections) and adds snapshot versioning: every observe carries a monotonically increasing version, every act declares the version it was built against, and a moved version is refused with STALE_SNAPSHOT before consent is even asked — an act can land on the correct element or be refused, never on the wrong one. Label matching is now exact after normalization on both sides (zero-width characters stripped, non-breaking spaces normalized). v0.2.20 enriches the snapshot without breaking its budget: page text is paginated (text_chunk / text_offset / text_total_chars / text_next_offset — page to the tail of a long page instead of losing it past 15k chars), every interactive carries its real href, bounding box, and viewport visibility, and every snapshot carries scroll state including a contentChanged flag for newly loaded content. Targeting gains fallbacks that still fail closed: label-only acts resolve exact first, then a unique normalized case-insensitive substring match reported as matchQuality: "fuzzy" (ambiguous matches refuse), plus click-by-coordinates and click-by-selector act types. v0.2.21 replaces the blanket per-site allow with a real whitelist: "Always allow on this site" writes a persistent entry scoped to the exact domain, the granted tier, and the concrete action types of its schema version — bound to the connector key that was active when granted, so key rotation wipes it. Subdomains never inherit a grant, action types added later are never silently covered, and T3 critical actions have no auto-allow path in any mode: the writer refuses to persist a T3 tier and the checker refuses T3 proposals, on top of the decision order that asks T3 first. Every whitelist-allowed action is stamped in the audit log ("allowed by whitelist: <domain>"), and older blanket site-allows migrate into scoped entries automatically. v0.2.22 adds the whitelist manager in the side panel: every entry shows its domain, coverage, grant and last-used dates, and schema version; entries can be added by typing a domain (normalized, with a punycode lookalike warning) or one click from the current tab, narrowed per action with checkboxes (T2 actions are now grantable the same way, from the manager and from the consent card), and revoked individually or all at once — effective immediately, mid-session included. Entries older than 30 days, and entries from an older schema, surface a one-click Keep/Revoke review (Keep re-confirms and adopts the current schema; nothing is silently permanent), and a master "Pause all grants" switch stops every auto-allow — whitelist and session grants alike — until it is switched off. The manager works entirely from the panel, connected driver or not. v0.2.23 makes the audit log visible: a live "Recent activity" feed in the panel shows the last ten finished actions in plain language — allowed, asked-and-approved, asked-and-denied, auto-allowed by whitelist (naming the exact granting domain), or blocked — updating the moment each action lands, and anything stopped carries a plain-English why and what would allow it. When a session ends (End session button, disconnect, driver abort, or the kill switch), a one-screen summary distills the session: "This session, Muse opened N pages, clicked N times…" with counts per action type and per site and every denial listed. The log, the feed, and the summary never leave the machine. v0.2.24 completes the action vocabulary: press_key (keys and combos like Ctrl+A, with Enter submitting its form), hover (menus open, and the result reports what appeared), select_option (dropdowns by value or visible text), drag (element-to-element or coordinate-to-coordinate), and set_value (values written through the native setter, so React-controlled inputs actually register them). Every new action passes the same consent tiers as click and type, joins the whitelist model as a separately grantable action — and is *not* covered by whitelist entries granted before it existed, until you re-confirm the entry. Keyboard-style input into password fields is refused on every path. v0.2.25 adds tab control: list, switch, close, pin, and open tabs, plus close-inactive-tabs — all T2 actions through the same consent gate, resolved against each tab's real site before the gate runs. Three hard rules are enforced in code, not promised in copy: the last tab in a window is never closed; closing the tab you are actively looking at always asks, even under a whitelist grant (and a tab that *became* active after its grant is not closed under it); and close-inactive always spares active, pinned, and audio-playing tabs. The side panel grows a Tabs card with the live tab list, duplicate detection, and its own close-inactive button. v0.2.26 is a same-day security fix: in v0.2.25 a live *session grant* could silently cover the forced prompt for closing the tab you are looking at (the whitelist path was already safe; the session layer was not). The session layer now excludes forced-ask actions, with a regression test pinning it — closing the viewed tab prompts under every grant type, no exceptions. v0.2.27 teaches the agent to wait and to read properly: wait_for (element, text, navigation, network-idle, or media-ended, always resolving inside a bounded timeout — no more blind sleeps), fetch_in_page (GET/POST in the page's own context at T2, so authenticated endpoints the snapshot can't see become readable; HTTPS only, credentials sent only to the page's own origin, bodies capped), and live media progress streaming (the driver gets currentTime/duration events as media plays instead of polling snapshots). v0.2.28 makes media honest: media control (play/pause/seek, T2) verifies playback by cross-checking that currentTime actually advances and names the failure when it can't start (autoplay-blocked, source-error, not-in-viewport, no-source); snapshots expose caption tracks (language, active track, cue counts) and caption text is retrievable for any time range; frame_grab returns a still of the video at a timestamp (DRM/cross-origin tainting is reported, never faked); and the driver keeps a per-player failure memory — two failed starts on the same player and it records NOT VERIFIED and refuses to retry instead of burning waits on every remaining video. v0.2.29 gives the agent ears: opt-in tab audio capture (the tabCapture permission is requested only from the side panel, by the user's own click; capture is T2 and per-site like everything else) streams the active tab's audio to the driver in ~1s Opus chunks — `driver listen` writes a transcribable .webm — while a red on-page pill shows the tab is being listened to, with its own Stop button; capture also stops itself if the tab navigates to another site or the driver disconnects, and stopping never needs a grant. Consent cards also gained a voice: distinct tones for waiting, grant, and deny, on the same sound switch. v0.2.30 hands you the controls the field converged on: a **Take over** button pauses the agent while you drive (its proposals queue — persisted, heartbeat-kept, nothing lost — and hand-back replays them through the gate in order); **plan approval** lets the driver propose up to 20 ordered steps that you approve once, after which the steps run without per-step prompts — except T3 steps, which still ask individually, always; the permission model simplifies to three **levels** — Light (T1/T2 act freely, T3 asks), Balanced (the recommended default: asks unless granted), Strict (asks everything; saved grants ignored) — with the per-site matrix still available underneath; and a new consent choice, **"Allow until I leave this site"**, grants a host in one tab until you navigate away, close the tab, or 15 minutes pass. v0.2.31 is a hotfix: the manifest was missing the offscreen permission, without which Chrome withholds the transport API entirely and Connect silently no-ops — the permission is declared, the failure now surfaces loudly in the panel, and a guard test pins it. v0.2.32 fixes the live transport flap that followed: the offscreen document is treated as mortal — the watchdog recreates it immediately when it is gone instead of inferring death from 75+ seconds of silence, the socket carries an application-level heartbeat so intermediaries can't idle-kill it, a relay send that races a document recreate is retried once instead of vanishing, and the driver's observe retries once across a flap (read-only, always safe). v0.2.33 gives every connector key a lifespan: at Generate/Rotate time you pick its lifetime (24 hours by default, 7 or 30 days, or never), and a key also retires on its own after 5 hours of cumulative driver-connected time or 200 executed actions — the big-task budget. Expiry is enforced locally in the extension, never interrupts a running task (a deadline that passes mid-session arms and fires at that session's disconnect, so small 1–5 hour tasks never notice), revokes the dead key at the relay so a late driver gets an explicit error instead of silence, and drops the ephemeral session/temporary grants — while the reviewed site whitelist survives, because expiry is hygiene and rotation (which still wipes everything) is distrust. The Key tab shows the countdown and usage, and says plainly when a key has expired and why. Keys created before this build carry no expiry until regenerated. ## Quick start

**Beta testers:** download the extension ZIP from [Releases](https://github.com/polesymbol/jarvis-browser-bridge/releases), unzip it, then load the `extension/` folder as below. **Developers:** clone this repo and load `extension/` from your checkout — same steps either way.

```bash
# 1. Extension: chrome://extensions → Developer mode → Load unpacked → extension/
#    Open the side panel, set relay URL to wss://relay.musebridge.avinyahub.com,
#    generate a connector key, Connect.

# 2. Driver
node driver/driver.js --relay wss://relay.musebridge.avinyahub.com --key <connector-key> observe
```

Or self-host the relay: `npm install && node relay/server.js` (deps live in the root `package.json`; see [relay/README.md](relay/README.md)).

## Security note

The relay terminates TLS and passes messages through — it stores nothing, but could technically observe traffic in transit. v2 moves to end-to-end encrypted payloads so the relay sees ciphertext only.
